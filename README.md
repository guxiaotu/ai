# 从评论看痛点：亚马逊手机壳低评分与用户反馈分析

本项目把既有亚马逊评论分析扩展为 INT6165 小组项目：描述低评分占比，检验图片标记与低评分的关联，并整理预设关键词规则命中的产品问题。报告与图表中的结果均来自用户提供的离线 Excel，不包含实时抓取。

目前已完成统计分析、敏感性检查、主题规则复用与四张报告图；120 条人工复核样本已抽取，**人工标签尚未填写，主题准确性尚未得到独立人工验证**。

## 数据来源与统计口径

来源为用户提供的 `卖家评论.xlsx`，首个工作表 `B0FH655984-Review(1190)`。共有 1,190 条记录，日期覆盖 2026-06-02 至 2026-09-11。文件 SHA-256：

```text
41056a105e52b535b5fdcf0682eac56aef53c9cd32abea487248ba2032260935
```

分析单位为一条评论记录。评论链接中的评论 ID 均唯一，原始星级与日期均有效，主分析保留全部 1,190 条。型号包含多个手机规格；工作表名不等于逐条购买商品的确证身份。链接中有 278 个形式有效的 ASIN，另有 187 条的 ASIN 参数为字面 `null`，不据此直接合并旧商品价格与销量表。人工复核也保留了“是否涉及其他商品”栏位。

低评分定义为 1—2 星，共 407 条，占 34.20%。主比较如下：

| 分组 | 1—2 星 | 3—5 星 | 合计 | 低评分比例 |
|---|---:|---:|---:|---:|
| 有图片标记 | 99 | 58 | 157 | 63.06% |
| 未标记图片 | 308 | 725 | 1,033 | 29.82% |

“有图片标记”指原表图片数量大于 0。其余 1,033 条图片数量为空白，编码为未标记；**空白不等于已确认没有图片**。两组比例差为 33.24 个百分点，95% 区间为 24.95—40.89 个百分点。此处描述的是导出样本中的关联，不说明上传图片导致低评分。

单个比例使用 Wilson 95% 区间，比例差使用未作连续性校正的 Newcombe 区间。主列联表报告未校正 Pearson 卡方检验，并以双侧 Fisher 精确检验核对；Fisher 采用固定边际下“概率不大于观测表概率”的双侧定义。比例比与优势比使用 log-Wald 区间；月份、手机型号分别作 Mantel–Haenszel 分层检查，不表示同时控制了全部混杂因素。置信区间和 p 值依赖独立观测等工作假设。

正文规范化去重仅作为敏感性检查：脚本把 HTML 换行转成句号分隔，清除其余 HTML，还原实体，整理空白和首尾句点，再统一大小写。此口径额外合并 27 条正文，得到 1,163 条。它与仅删除 HTML 的口径可能略有不同；正文相同不能证明是同一评论，因此主结果不采用正文去重样本。

五项负向规则在 407 条低评分评论中匹配；默认同时使用原文标题、正文及已有中文译文。每条评论在同一规则下最多计一次，但可命中多条规则。五项命中数依次为 107、37、29、28、15；至少命中一项的独立评论为 183 条，未命中任何一项为 224 条。命中率不能解释为已确认的投诉率，未命中也不代表没有问题。规则开发是文本归纳步骤，不是已经训练并验证的机器学习模型。

导出时的排序、筛选、覆盖范围和收集机制未获得完整说明；用户是否评论、是否附图也并非随机。评论之间可能因商品或评论者而相关。首尾月份不完整，月度数量不能当作销量趋势。研究问题在查看过数据后确定，当前结果属于探索性分析；120 条样本在这份低评分数据内部随机抽取，也不会使原始导出样本成为总体随机样本。

## 运行方法

### 1. Python 环境与输入文件

本次运行使用 Python 3.12.14。分析需要 pandas、numpy、openpyxl；绘图还需 reportlab。已有这些依赖时无需重新安装。其他机器可在独立 Python 环境中安装本目录 `requirements.txt` 指定的版本：

```bash
python -m pip install -r requirements.txt
```

输入应保留原始 Excel 列名，至少包括：`型号`、`标题`、`标题 (翻译)`、`内容`、`内容(翻译)`、`星级`、`图片数量`、`评论时间`、`链接`。代码读取首个工作表；链接必须能解析评论 ID，星级必须为 1—5，日期须有效。同一评论 ID 若数据冲突，或图片数量为负，脚本会报错，不会静默删掉。

### 2. 复算统计结果

在本项目目录运行，替换示例中的 Excel 路径：

```bash
python 分析代码.py "/你的数据目录/卖家评论.xlsx" --out "./数据结果"
```

输入参数是必填的 Excel 路径；`--out` 是结果目录，默认是运行命令时所在目录下的 `数据结果`。`主题规则.json` 必须与 `分析代码.py` 同目录。程序只读取原始 Excel，但会覆盖结果目录中同名的 JSON 和 CSV；开始人工标注前，应另存一份标注文件。若只想核对复算，可使用 `--out "./复算结果"`，保留已交付结果。

当前 Codex 环境可以直接使用已配置的 Python：

```bash
"$HOME/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3" \
  分析代码.py "/你的数据目录/卖家评论.xlsx" --out "./数据结果"
```

### 3. 生成图表

```bash
python 生成图表.py
```

绘图脚本没有命令行路径参数，固定读取**脚本所在目录**的 `数据结果/统计结果.json`，输出到其 `图表/`。生成 SVG 为 1000×500，PNG 为 2000×1000。图表标题、日期说明、固定坐标轴和五个主题布局针对本次数据设计，换新数据时必须同步检查说明文字与图形是否仍适用。

除了 Python 依赖，PNG 转换还需要 Node.js 与 `sharp`；本次使用 Node.js 24.19.0、sharp 0.35.4。默认位置是当前用户目录下的 Codex bundled runtime，无需额外配置。系统字体默认用 macOS 的 `Arial Unicode.ttf` 计算文字宽度；SVG/PNG 显示时优先使用 PingFang SC、Heiti SC 或 Hiragino Sans GB。

跨机器运行时，可通过以下环境变量指定实际位置：

```bash
export CODEX_CHART_NODE="/绝对路径/node"
export CODEX_CHART_SHARP="/绝对路径/node_modules/sharp"
export CODEX_CHART_FONT="/绝对路径/含中文字形的字体.ttf"
python 生成图表.py
```

`CODEX_CHART_FONT` 必须是 ReportLab 能读取的含中文 TrueType 字体。它负责字宽计算，不等于把字体嵌入 SVG；目标系统还须让 sharp 的 SVG 渲染器找到中文字体或中文字体回退。非 macOS 环境的字体路径及字体匹配没有在本次验证过，应逐张检查生成的 PNG 是否出现方框或标签重叠。若只需要阅读或提交，直接使用已经检查过的 PNG，不需要运行绘图程序。

统计和绘图脚本不会自动更新 Word 报告正文。重新生成数据后，应检查并更新报告中的表格、文字和插图，避免报告与新结果不一致。

## 120 条人工复核怎么完成

样本从 407 条低评分评论中等概率、不放回抽取，随机种子为 6165。当前文件中的全部人工标签均为空。其用途是评价五个问题主题在**低评分子样本**中的识别表现，不能直接评估所有星级中的表现。

1. 另存一份标注文件，保留 `review_id` 与 `source_row`。两位组员先共同确认主题定义，再分别独立标注，不查看规则命中证据或对方结果。
2. 对五个主题分别填写 `1`（明确表达相应负面问题）、`0`（未表达）或 `U`（不确定）。主题应按问题含义判断，不能仅因出现产品部件名就填 1。正面陈述、否定问题的表达及仅作购买介绍，不算对应的负面问题。
3. 原文优先，译文辅助。抽样文件包含原文标题、标题译文、正文和正文译文，应一起查看，使人工评估和自动匹配覆盖相同材料。需要核实时，可通过 `source_row` 回到原始 Excel；源行号是含表头的 Excel 行号。
4. “做工耐用性”检查开裂、破损、易坏等；“磁性部件”对应磁性部件脱落；“充电”对应无法充电或充电不正常；“颜色”对应实物颜色与预期或描述不符；“打滑”对应手感滑、容易滑落。还应单独标记是否明显涉及其他商品，并在备注说明。
5. A、B 完成后逐项讨论分歧，保留两份独立判断，把最终结果写入“协商结果”；无法判定时保留 U，不强行改为 0。
6. 用 `review_id` 对接 `主题命中证据.csv`，逐主题比较规则是否命中与协商标签。协商 1/0 可形成 TP、FP、FN、TN；U 应单独报告并说明排除口径。完成后再计算标注一致性、精确率和召回率。不能在标注前填写这些结果。

此随机样本同时允许发现误判和漏判，但罕见主题可能只有很少正例。若后来专门补抽命中评论用于检查错误，应将补抽样本与这 120 条区分，不能无权重混合后声称仍是等概率估计。若依据这批标注修改规则，再报告同一批样本上的准确率，则属于开发集表现；正式评估应使用另外保留的复核样本。

## 相较旧项目新增了什么

旧项目提供评论清洗、关键词规则、命中证据和多张描述性图表。本次保留规则并记录其哈希，新增了明确的统计研究问题、低评分比例区间、图片标记列联表、比例差与效应大小、假设检验、分月及型号分层检查、正文去重与低评分定义敏感性、仅原文主题比较，以及待完成的人工复核材料。报告将这些结果组织为“问题—方法—结果—局限”的论证。

目前没有新增在线抓取、销量预测、数据库部署或训练后的情感模型。提交时仍需由组员补充姓名、学号、实际分工，确认旧项目复用符合课程规定，并按实际完成情况填写人工复核结果。

## 方法核对来源
